# 业务图片统一处理方案

> 本文是项目业务图片上传、裁剪、编码、存储和展示的唯一现行规范。项目目前尚未上线；其他文档中的历史迁移记录只说明当时发生过什么，不能作为新增模块或修改图片链路的实现依据。

## 1. 最终方案

所有业务模块共用同一条链路：

1. 小程序选择 JPEG、PNG 或 WebP 原始文件。
2. 需要裁剪时，共享 `image-cropper` 只负责交互和本地预览，返回原始文件路径及归一化裁剪框 `{ x, y, width, height }`。
3. 小程序上传原始文件，并把裁剪框作为 `image_crop` 表单字段发送；不上传本地预览图。
4. 服务端完成登录与权限校验、文件类型和大小校验、微信图片内容安全检查。
5. 服务端用原始文件按固定顺序处理：读取方向信息并自动转正 → 按裁剪框裁剪 → 最长边限制为 2560 像素且不放大小图 → 编码为有损 WebP（质量 88，透明通道质量至少 90）→ 去除 EXIF 等非必要元数据。
6. 腾讯云私有 COS 只保存一张不可覆盖、带版本标识的高清主图；数据库只保存稳定对象路径，并在 `image_assets` 记录对象归属、模块、实际字节和 MIME。
7. 页面列表、详情、预览和打印共用这张主图。读取时由服务端签发 6 小时有效的私有访问地址。

当前处理版本为 `master-v1`，普通图片上传硬上限为 10 MB，解码像素上限为 5,000 万。

## 2. 为什么这样处理

- 上传原始文件和裁剪坐标，让服务端只进行一次有损编码，避免“小程序先压一次、服务端再压一次”造成清晰度继续下降。
- 归一化坐标不依赖手机屏幕尺寸或原图像素，服务端可以在自动转正后的真实图片上得到一致裁剪结果。
- 统一的最长边、格式和质量让各模块的清晰度、流量和存储成本可预测，也避免菜品、活动、关键节点等模块各自演化出不同规则。
- 当前数据规模下只存一张主图，能避免多对象、重复处理、私有签名和删除回收的额外复杂度。列表下载量是否需要进一步优化，应以真实监控数据为依据，但不能由单个模块自行增加缩略图。
- COS 存图片，Supabase 只保存业务记录和资产台账。图片空间统计直接聚合 `image_assets`，不会在用户打开页面时遍历 COS。

## 3. 强制边界

模块可以决定是否裁剪、裁剪框形状和宽高比，例如头像固定 1:1、活动封面固定 4:3；模块不得决定输出像素、格式、质量、压缩次数、主图版本或是否额外保存缩略图。

不得在页面或业务服务内新增以下行为：

- 把 Canvas 预览图当作业务上传文件；
- 在上传前转成 JPEG、WebP 或其他有损格式；
- 为某个模块单独设置 1080、1440、1920 等输出尺寸或不同质量；
- 长期保存手机原始文件、列表图、缩略图或腾讯云数据万象动态变体；
- 通过修改已签名 URL 的路径来请求另一种图片规格；
- 绕过共享 `image-cropper` 自建裁剪弹层；
- 绕过服务端格式、像素、内容安全和权限校验。

如未来真实数据证明必须改变图片策略，应先形成一份全局替代方案，同时更新所有模块、处理版本、迁移、测试和本文；不能以“临时优化”为由新增并行方案或兼容分支。腾讯云数据万象等可能产生处理费用的能力，必须先明确成本和缓存模型后才能纳入全局方案。

## 4. 本地预览与例外

`image-cropper` 可生成最长边不超过 1080 像素的本地 PNG，唯一用途是让用户立即预览裁剪结果。这个临时文件不进入业务上传、COS 或 `image_assets`。

文字卡片编辑器会在本地消费裁剪结果来生成最终卡片，它不上传为上述业务图片，因此属于本地导出流程，不得把它的 Canvas 参数反向用于业务图片策略。

## 5. 替换、删除与数据一致性

- 新增：处理成功并写入 COS 后登记 `image_assets`；登记失败时回滚刚上传的 COS 对象。
- 替换：先上传并登记带随机版本路径的新图，再切换业务记录，最后删除旧对象和旧台账；切换失败时删除新对象。
- 删除：只删除已确认属于当前用户、且不再被有效业务记录引用的对象；菜单历史等仍被引用的归档图片是有效业务数据，不是孤儿文件。
- 数据库永远保存稳定对象键，不保存带时效签名的 URL。

本次实现没有改动数据库结构和现存业务数据。旧图片不会被重新编码；用户重新上传后才进入 `master-v1` 链路。

## 6. 代码归属

- 小程序裁剪协议：`src/types/images.ts`
- 共享裁剪交互：`src/components/image-cropper/`
- 统一上传封装：`src/services/request.ts`
- 服务端表单解析：`server/http/multipart-image.mjs`
- 唯一图片规格与处理顺序：`server/lib/image-processing.mjs`
- COS 与资产台账：`server/domains/shared/image-storage.mjs`

新增图片模块必须复用以上入口。图片规格只能在 `STANDARD_IMAGE_PROFILE` 修改；改变规格时必须同步提升 `IMAGE_STORAGE_VERSION`，否则不同内容可能使用相同版本语义。

## 7. 变更验收

每次修改图片链路至少验证：

- 裁剪坐标只能位于 `[0, 1]`，非法或越界输入由服务端拒绝；
- EXIF 方向先归一，再执行裁剪；输出不保留方向和 EXIF 元数据；
- 大图缩小、小图不放大、透明通道保留、损坏图和超像素图被拒绝；
- 每次业务上传只生成一个 `master-v*` WebP 对象，并同步一条资产台账；
- 所有上传页面发送原始文件路径和同一份裁剪协议；
- `pnpm run typecheck`、完整服务端测试和 `git diff --check` 通过。
