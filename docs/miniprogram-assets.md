# 微信小程序资源放置约定

## 目标

微信开发者工具的代码质量检查要求，代码包内的图片和音频资源合计不超过 200 KB。这里的 200 KB 是包内媒体资源总量约束，不是“每个文件都可以接近 200 KB”。

项目同时由 Nginx 提供静态文件服务：服务器上的 `public/` 目录映射到 `https://gufeifei.cn/`。因此，大部分图片和音频不需要随小程序代码一起上传。

## 放置规则

### 放在 `src/` 的资源

只有同时满足以下条件的资源才放在 `src/`：

- 小程序首屏或关键交互必须立即使用；
- 离线或网络失败时仍必须显示；
- 文件已经充分压缩，且不会让 `src/` 内图片和音频总量超过 200,000 字节；
- 代码中存在明确引用，不是备用稿、原始图或历史文件。

示例：小尺寸品牌标志、必须随包加载的基础背景。

### 放在 `public/` 的资源

以下资源统一放在 `public/`：

- 大图、照片、插画、音频；
- 可通过网络按需加载的业务图片；
- 备用品牌图、设计源文件、打样图、打印素材和历史素材；
- 当前没有被小程序引用，但需要在仓库中保留的文件。

目录与访问地址一一对应，例如：

```text
public/assets/brand/logo.png
https://gufeifei.cn/assets/brand/logo.png
```

小程序需要使用服务器资源时，直接引用对应的 HTTPS 地址。不要在 `src/` 和 `public/` 中保留同一文件的两份副本。

## 修改前检查

新增或替换媒体资源前，先确认：

1. 页面是否真的需要随包加载；
2. `src/` 中是否已有等价资源；
3. 能否放到 `public/` 并按需加载；
4. 资源 URL 是否使用 `https://gufeifei.cn/`；
5. 服务器部署时是否会同步对应的 `public/` 文件。

## 验证

提交前运行：

```bash
node --test server/miniprogram-package.test.mjs
pnpm run typecheck
```

然后在微信开发者工具中重新编译并执行“代码质量 → 重新扫描”，确认：

- 主包尺寸小于 1.5 MB；
- 图片和音频资源检查通过；
- 主包未使用 JS 检查没有因错误分包而新增失败项。

自动测试会统计 `src/` 中常见图片和音频格式的总大小，并在超过 200,000 字节时失败。微信开发者工具的复扫结果仍是最终验收依据。
