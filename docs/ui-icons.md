# UI 图标使用规范

## 目标

界面中的常用工具操作优先使用小图标表达，减少重复文字和控件宽度，让顶部工具栏、卡片操作区和高频页面保持简洁。图标统一复用全局 `app-icon` 组件及 `src/assets/icons/lucide/` 中的公共资源，不在页面内自行绘制或复制图标。

在含义清晰且已有共享图标可用时，默认使用图标，不再显示同义文字。新增短文字按钮、角标或状态提示前，应先检查 `app-icon` 是否已有可准确表达的图标；这条原则同时适用于常用操作和锁定、完成、提醒等通用状态。只有存在歧义、属于业务专有概念或操作后果需要明确说明时，才保留可见文字。

## 优先使用纯图标的场景

当操作含义常见、单一，并且图标已经形成稳定认知时，使用纯图标按钮，不再在图标旁重复添加文字。例如：

- 设置、返回、关闭、更多。
- 新增、编辑、删除。
- 搜索、筛选、刷新、下载、打印。
- 图片预览、上传图片、清除内容等常用工具操作。

推荐写法：

```xml
<view
  class="settings-button"
  role="button"
  aria-label="人生节点设置"
  bindtap="handleSettings"
><app-icon name="settings-2" size="28" /></view>
```

不要同时显示设置图标和“设置”文字，也不要用字符、Emoji 或页面内临时 SVG 代替已经存在的公共图标。

## 必须保留文字的场景

以下内容不能为了追求简洁而强行改成纯图标：

- 图标含义不明确、属于业务专有概念，或用户需要猜测其作用。
- Tab、筛选项、表单字段、布局选项等需要明确区分含义的内容。
- 登录、保存、提交、确认支付等需要清晰表达结果的主要操作。
- 同一区域出现多个外形相近、难以仅靠图标区分的操作。

有歧义时优先保留短文字；图标简洁不能以理解成本为代价。

## 尺寸与可访问性

- 纯图标按钮必须提供准确的 `aria-label`，不能只依赖视觉图形传达含义。
- 非交互状态图标不需要扩展为按钮点击区，但状态含义必须进入所在控件的 `aria-label`，视觉图标本身应对辅助技术隐藏，避免重复朗读。
- 图标本身通常使用 `24rpx` 至 `30rpx`，点击区域不得小于 `56rpx × 56rpx`。
- 紧凑工具栏中的图标按钮应保持一致的点击区域、对齐方式和视觉重量。
- 深色按钮使用反色图标；颜色继续遵循 `docs/ui-colors.md`，不得在页面样式中硬编码。
- 图标按钮不额外使用固定文字宽度；如必须显示文字，则按内容宽度加均衡的左右内边距。
